# 遊戲式學習設計與製作

把學習成果落實在玩家必須採取的行動、遊戲規則和決策後果中。遊戲的完成或高分本身不代表學會；設計也要讓玩家能看懂結果、調整想法，並讓教師或評量取得符合目標的學習證據。

## 使用時機

當使用者要構想、設計、製作、改編或評估數位遊戲式學習體驗時使用本 Skill。依請求提供概念提案、遊戲設計文件、玩法規格、課堂流程、原型或程式實作。一般娛樂遊戲若沒有教學目標，不套用本 Skill 的教學對齊流程。

先查看專案中的 `AGENTS.md`、現有設計文件、程式碼與技術堆疊，沿用專案既有慣例。保留使用者指定的題材、對象、玩法、平台與範圍；不要因參考教材的供水案例而把水資源設定成預設題材。

## 設計流程

1. **掌握學習情境。** 確認學習者、先備知識、課程或訓練情境、遊玩時間、個人或合作方式、平台及可用資源。先使用使用者已給的資訊；非關鍵資訊不足時，提出合理假設並標示。只有缺少資訊會改變核心玩法或交付物時，才先問一個聚焦的問題。

2. **寫出可觀察的目標。** 說明學習者在什麼條件下能做出什麼行動，以及如何看出做得好。避免只寫「了解」或「熟悉」。辨別目標主要涉及事實與術語、程序、概念解釋或策略判斷，並據此安排玩法與證據。

3. **先確定玩家要做的學習行動，再選遊戲形式。** 分清模擬、遊戲與遊戲化：模擬讓玩家改變條件並觀察模型；遊戲在目標與規則下加入需要取捨的行動；遊戲化則是在原有非遊戲活動中加入點數、徽章等元素。選擇能提供所需練習的形式，不為了獎勵或表面趣味而增加系統。

4. **建立核心循環和有意義的選擇。** 描述玩家的目標、遊戲狀態、可採取的行動、限制、規則及行動後果，再串成「查看資訊 → 作決策 → 看結果 → 解釋或調整」的循環。每個重要選擇都應讓不同方案在成本、風險、時間或其他條件上有所取捨；規則和結果須清楚到足以推理。讓完成核心目標需要運用預定的學習內容，避免靠猜答案、反覆點擊或累積裝飾性分數繞過學習行動。

5. **把目標和玩法逐項對齊。** 設計時以小表格連接「學習目標｜玩家行動｜規則及結果｜回饋｜學習證據」。若某個目標沒有對應的玩家行動，或玩家能不理解目標內容也輕易通關，修改玩法或縮小目標。

6. **安排挑戰、回饋與重試。** 從較少條件開始，再逐步加入需要同時考慮的資訊。回饋要指出行動如何造成結果及可能原因，而不只顯示答錯、扣分或通關；需要時提供提示、示範、紀錄回看或分段重試，並隨能力進步減少支援。把回饋、獎勵和評量視為不同功能，不以獎勵代替解釋或學習證據。留意文字可讀性、顏色辨識、字幕、操作方式與節奏是否阻礙學習者取得資訊。

7. **安排遊戲與教學的銜接。** 在課堂使用時，規劃遊玩前的目標與規則說明、遊玩中的觀察與提問，以及遊玩後的討論、概念整理和新情境應用。課後問題應讓學生說明當時依據、結果與取捨，並檢查能否將理解用於不同條件；不要假設單靠遊玩就會自動遷移。

8. **用小型原型回答明確問題。** 先說清楚原型要檢查什麼，例如學生是否讀懂規則、會不會比較方案，或能否解釋結果。只製作足以觀察該問題的部分，記錄玩家做了什麼、說了什麼，以及卡住的位置；把觀察到的現象和推測原因分開，再據此調整。使用者要求實作時，依現有專案架構完成最小可玩版本，避免未經要求擴大範圍。

9. **分開判斷參與和學習。** 依目標選擇證據：術語可用情境辨認，程序要看操作，概念要看解釋，策略要看決策理由。分別看待參與、當下學習、延後保留及新情境遷移；遊玩時間、點擊次數、重試次數或總分只能描述部分遊玩行為，不能單獨證明理解。若比較教學方式，說明時間、先備能力、教師支援與評量條件可能造成的影響。

## 交付物

跟隨使用者要求的形式與細節。若使用者要完整設計文件，優先包含：

- 一句話概念、目標學習者與使用情境
- 可觀察的學習目標
- 核心循環、規則、選擇與主要遊戲狀態
- 學習目標對齊表
- 挑戰進程、回饋、支援、失敗與重試安排
- 遊玩後的引導或評量證據
- 目前假設、範圍和待確認的設計問題

若使用者只要一個點子、單一機制或程式修改，就只交付完成該項所需的內容，不強加整份設計文件。使用與使用者相同的語言；本專案未指定時，以繁體中文撰寫。

## 完成檢查

- 每個主要學習目標都對應到玩家實際要做的行動和可觀察證據。
- 核心玩法的選擇有可理解的結果，回饋能協助玩家解釋或修正想法。
- 挑戰、提示與重試支持學習者進步，失敗能提供下一步可用的資訊。
- 若有教師或課堂情境，遊戲前、中、後的安排彼此銜接。
- 評量沒有把投入或遊戲分數直接當成學會的證明；未確定的假設清楚標示。
